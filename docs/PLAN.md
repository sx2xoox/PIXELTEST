# Atelier 기획안 v2 — 외부 서비스 없이 Claude 혼자 디자이너가 되는 프로그램

> **원칙:** 이미지 생성 AI(PixelLab, Figma AI, DALL·E 등)를 쓰지 않는다.
> Claude가 가진 능력(**코드 작성 + 이미지 보기 + 디자인 지식**)만으로 고품질 디자인을 만든다.
> 사용하는 것은 로컬 프로그램(Chromium 렌더러, Node.js)과 오픈 라이선스 폰트뿐이다.

---

## 1. 문제 재정의

Claude가 디자인을 못 하는 이유는 "그림 실력"이 없어서가 아니라 **작업 환경이 없어서**다.

| 사람 디자이너가 가진 것 | 기존 Claude | Atelier가 주는 것 |
|---|---|---|
| **손:** 붓, 펜, 도형 툴 | 좌표를 하나하나 적어야 함 → 딱딱한 픽셀아트, 단순 도형 | **고수준 그리기 어휘:** 점 몇 개 → 매끄러운 곡선, 붓 획, 유기적 덩어리, 산맥, 입체 음영, 질감, 빛 |
| **눈:** 그리면서 계속 확인 | 결과를 보지 못하고 한 번에 출력 | **렌더 → 비평 시트 → Claude가 직접 봄 → 수정** 루프 |
| **감각:** 색 이론, 타이포, 구도 훈련 | 지식은 있지만 쓰는 절차가 없음 | **디자인 지식 스킬:** 절차, 체크리스트, 토큰 기반 색 체계 |
| **검수:** 흑백 보기, 실눈 뜨고 보기, 축소해 보기 | 없음 | 자동 비평기가 대비, 넘침, 겹침, 위계, 명도, 균형, 색 절제, 고아 단어를 측정 |

즉 **손(엔진) + 눈(렌더/비평) + 감각(스킬)**을 Claude 바깥에 코드로 만들어 붙이면,
Claude 혼자서도 디자이너처럼 일할 수 있다.

## 2. 구조

```
          ┌──────────────── Claude (아트 디렉터) ─────────────────┐
          │  브리프 → 콘셉트 3개 → 선택 → 다듬기 → 검수 → 전달        │
          │        ▲  .claude/skills/atelier/SKILL.md (절차와 지식)  │
          └────┬───┴──────────────────────────────────────▲──────┘
     장면 DSL  │ (JSON / JS)                    비평 시트를  │ 눈으로 봄
               ▼                                           │
 ┌───────────────────────────── atelier 엔진 ──────────────┴───────┐
 │ color.js   OKLCH 팔레트, 톤 램프, 토큰, WCAG 대비                 │
 │ geom.js    스플라인, 붓 획, blob, ridge, squircle, star, 시드 난수 │
 │ scene.js   DSL → SVG (그라디언트, shade 입체, 필터 효과, 질감,    │
 │            scatter/repeat 절차적 배치, 클립, 블렌드, 타이포)       │
 │ render.js  로컬 Chromium 렌더 → PNG + 측정 + 비평 시트 + 비교 시트 │
 │ critic.js  디자인 규칙 → 문제 목록, 수정 방법, 점수               │
 └─────────────────────────────────────────────────────────────────┘
```

### 비평 시트 한 장에 담는 것 (사람 디자이너의 검수 습관을 옮김)
원본 · 3분할/중심/무게중심/텍스트 대비 오버레이 · 흑백(명도 구조) · 블러(스퀸트 테스트)
· 96/48/24px 축소(식별성) · 실제 사용된 색 덩어리 · 디테일 많은 4칸 200% 확대 · 규칙 비평

## 3. 검증 결과 (이번 프로토타입으로 실측)

| 작업 | v1 | 비평에서 나온 지적 | v2 |
|---|---|---|---|
| 앱 아이콘 | 규칙 100점, 하지만 **눈으로 보면** 텐트가 배경에 묻히고 24px에서 안 보임 | 초점 부재, 레이어 간 명도 차이 부족 | 따뜻한 텐트와 차가운 밤의 온도 대비, 대기원근 3층 → 24px에서도 식별 |
| 한글 포스터 | **52점**(레이아웃 엔진 도입 후에는 고아 단어가 자동 해결되어 58점): 대비 미달 2건, 대비 빠듯 1건, 고아 단어, 밋밋한 명도 | 비평기가 자동 검출 | **100점**, 눈으로 봐도 명도 구조·위계·초점이 명확 |

**교훈:** 규칙 비평만으로는 부족하고(아이콘 v1이 100점), Claude가 시트를 직접 보는 단계가 반드시 필요하다.
두 가지는 서로를 보완한다.

## 4. 로드맵 (모두 로컬, 외부 생성 AI 없음)

| 단계 | 모듈 | 내용 | 완료 기준 |
|---|---|---|---|
| ✅ **P0** | 코어 | DSL, 색 체계, 형태 엔진, 렌더러, 비평기, 시트, 스킬 | 아이콘과 포스터로 렌더→비평→수정 루프 시연 |
| ✅ **P1** | 레이아웃 엔진 | 실측 줄바꿈, 한글 줄머리 금칙, 고아 단어 방지, 의미 단위 균형 줄바꿈, 자동 맞춤(fit), stack 배치, 반응형 규격(`--formats`) | ✅ 한 함수로 4개 규격 생성, 넘침·겹침 0건 (`examples/market.mjs`). 남은 일: grid 배치, 베이스라인 그리드 |
| **P2** | 일러스트 부품 라이브러리 | 매개변수형 부품: 나무, 구름, 건물, 식물, 동물, 얼굴/캐릭터(표정·포즈 파라미터), 소품. 모두 `shade`와 빛 방향을 공유 | 부품 30종, 장면 조립만으로 일러스트 완성 |
| **P3** | 페인팅 엔진 | Canvas 기반 래스터 붓: 수채 번짐, 구아슈, 연필, 잉크, 에어브러시. 종이 질감, 붓 압력 곡선 | "손으로 그린" 질감의 일러스트 |
| ✅ **P4** | 픽셀아트 모듈 | 픽셀 캔버스(브레젠험, 다각형, 문자 지도), 색상 이동 램프, 자동 돔 음영, 선택적 외곽선, 타일링 노이즈, 디더링, 스프라이트 비평 | ✅ 블록 텍스처 12종(모두 타일링), 아이템 3종. 남은 일: 벡터 장면 → 픽셀화, 2D 프레임 애니메이션 |
| ✅ **P4-MC** | 마인크래프트 모듈 | 재질 16종, 큐브 모델 DSL, 아틀라스 자동 패킹, Java 규칙 검증, `.bbmodel`(5.0)·Java JSON·리소스팩 내보내기, three.js 미리보기(게임식 면 음영, 실루엣, 애니메이션 프레임) | ✅ 블록 모델 1종, 엔티티+걷기 애니메이션 1종, 리소스팩 zip. 남은 일: bedrock `.geo.json`/애니메이션 직접 내보내기, 블록스테이트 변형(방향·연결), 아머/플레이어 스킨 템플릿 |
| ◐ **P5** | 3D · 모션 | three.js 로컬 렌더(큐브 모델은 완료) → 로우폴리·아이소메트릭·클레이 스타일 확장, CSS/SVG 애니메이션 → ffmpeg 영상/GIF | 아이소메트릭 방 1개, 로고 애니메이션 1개 |
| **P6** | 비평 고도화 | 형태 겹침/접선(tangent) 검출, 시선 흐름 추정, 정렬선 검출, 그리드 이탈 측정, 시안 간 다양성 측정 | 비평 지적과 사람 평가의 일치율 측정 |

| **P8** | MCP 서버화 | `render`, `critique`, `compare`, `palette`를 MCP 도구로 노출 | 어느 Claude 세션에서든 같은 파이프라인 사용 |

## 4.5 마인크래프트 모듈 검증 기록
| 항목 | 첫 렌더에서 발견한 것 | 수정 |
|---|---|---|
| 판자 텍스처 | 결과 이음매가 사라짐 → 원인은 난수기 xorshift가 작은 시드에서 0 근처 값을 냄 | mulberry32로 교체(전체 품질 개선) |
| 원목 텍스처 | 비평기가 세로 이음새 검출 → 껍질 결이 아래 경계에서 잘림 | 결을 위로 감아 이어지게 |
| 랜턴 기둥 | 랜턴이 작고 "랜턴"으로 읽히지 않음, 발광 면에 음영이 적용됨 | 4×5로 확대, 철창 바깥 큐브 + 발광 안쪽 큐브, 발광 면 무음영 |
| mossling | 돌 질감이 캐릭터 크기에서 거칠고, 머리와 몸이 구분 안 됨, 실루엣이 병 모양 | 대비 0.9로 낮춤, 명도 3단 분리, 머리 폭 10으로 확대 |
| 단검 | 코등이와 손잡이가 뭉침, 자동 외곽선 때문에 색이 21개 | 진행 방향 벡터 기준으로 재배치, 외곽선 색을 색상 계열별로 통일(13색) |
| `.bbmodel` | Blockbench 소스 확인 결과 4.x 파일은 애니메이션 x/y 회전이 반전되어 로드됨 | 5.0 형식(groups + outliner 참조)으로 내보내기 |

## 5. 품질 평가 방법
- **벤치 브리프 30개(부문별 고정):** 기능을 바꿀 때마다 다시 돌려서 점수와 시트를 보관한다(회귀 확인).
- **비교 기준:** ① 기본 Claude가 SVG를 한 번에 출력한 결과 ② Atelier 1회 렌더 ③ Atelier 3회 루프. 사람이 이름을 가리고 비교한다.
- **자동 지표:** 비평 점수, 반복 횟수, 대비 통과율, 넘침/겹침 0건 여부.

| 비전 판단이 작은 결함을 놓침 | 디테일 많은 영역을 자동으로 확대해 보여주고, 정량 규칙을 병행한다. |
| 렌더 시간 | 렌더 1회 약 1~2초라 반복에 문제없음. 브라우저 인스턴스를 재사용한다. |
