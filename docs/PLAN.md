# Claude 독자 디자인 시스템 기획안 (가칭: **Atelier**)

> 목표: Claude가 "코드로 찍는 픽셀아트" 수준을 넘어, UI·브랜딩·일러스트·게임 에셋·포스터·3D·모션까지
> **스스로 기획 → 제작 → 검수 → 수정**하는 고품질 디자인 파이프라인을 갖추게 한다.

---

## 1. 진단 — 왜 Claude는 디자인에 약한가

| 구분 | 내용 |
|---|---|
| **근본 제약** | Claude의 출력은 텍스트 토큰뿐이다. 래스터 픽셀을 직접 "그릴" 수 없고, 좌표·색값을 글로 나열하는 방식이라 손그림 같은 유기적 형태에 약하다. |
| **진짜 병목** | 결과물을 **보지 못한 채 한 번에 출력**하는 open-loop 구조. 사람 디자이너도 화면을 보지 않고 그리면 망가진다. |
| **공간 감각** | 겹침, 정렬 오차, 비율 문제를 코드만 보고는 잘 알아채지 못한다. |
| **이미 가진 강점** | ① 코드(SVG, HTML/CSS, Canvas, GLSL, Blender Python)를 잘 쓴다 ② **이미지를 볼 수 있다(비전 입력)** ③ 여러 도구를 엮어 쓸 수 있다 ④ 디자인 이론(그리드, 타이포, 색채)을 알고 있다 |

**결론:** Claude를 "직접 그리는 손"으로 만들 게 아니라 **아트 디렉터 겸 테크니컬 아티스트**로 만든다.
손 역할은 ① 코드 렌더러 ② 외부 생성 모델이 맡고, Claude는 기획·조율·검수·수정을 맡는다.
핵심은 **렌더 → 눈으로 확인 → 비평 → 수정**을 반복하는 closed-loop다.

## 2. 핵심 아키텍처

```
 사용자 요청
     │
     ▼
┌──────────────┐   ① 브리프 정리: 목적, 대상, 톤, 제약, 레퍼런스
│ Brief Agent  │──▶ Design Brief IR (JSON 스펙)
└──────────────┘
     │
     ▼
┌──────────────┐   ② 부문/스타일별로 맞는 엔진 선택
│   Router     │
└──────────────┘
     │
     ├─▶ [A] 코드 엔진     SVG · HTML/CSS · Canvas · GLSL · three.js · Blender(Python)
     ├─▶ [B] 생성 엔진     PixelLab(픽셀/게임 에셋) · Figma generate_image(gpt-image / gemini)
     └─▶ [C] 하이브리드    생성 이미지 → 배경 제거 · 벡터화 · 업스케일 · 코드 레이아웃과 합성
     │
     ▼
┌──────────────┐   ③ 실제 픽셀로 렌더 (Playwright Chromium, resvg, ffmpeg, Blender)
│  Renderer    │──▶ PNG / 프레임
└──────────────┘
     │
     ▼
┌──────────────┐   ④ 비평: 비전(Claude가 직접 봄) + 정량 지표
│   Critic     │      - WCAG 대비, 팔레트 이탈 ΔE(OKLab), 그리드/정렬 오차,
│              │        텍스트 넘침, 여백 균형, 해상도/아티팩트
└──────────────┘
     │ 점수 < 기준 → 수정 지시를 붙여 ②/③으로 되돌림 (최대 N회, best-of-K 후보 비교)
     ▼
┌──────────────┐   ⑤ 결과물 + 편집 가능한 원본(SVG/HTML/레이어/.fig) + 디자인 토큰
│  Exporter    │
└──────────────┘
```

### 2.1 Design Brief IR (모든 엔진이 함께 쓰는 스펙)
```json
{
  "domain": "logo | ui | illustration | pixel_asset | poster | 3d | motion | brand_system",
  "purpose": "앱 런처 아이콘", "audience": "20~30대",
  "mood": ["따뜻함", "미니멀"], "palette": {"mode": "oklch", "seed": "#E8590C"},
  "typography": {"scale": "1.25", "families": ["Pretendard"]},
  "canvas": {"w": 1024, "h": 1024, "grid": 8},
  "constraints": ["2색 이하", "16px에서도 식별 가능"],
  "references": ["moodboard/*.png"],
  "deliverables": ["svg", "png@1x,2x,4x"]
}
```
IR이 있으면 엔진을 바꿔도 의도가 유지되고, Critic이 무엇을 기준으로 채점할지 정해진다.

### 2.2 Critic 루프 (품질을 좌우하는 부분)
1. **비전 비평:** 렌더한 PNG를 Claude에게 다시 보여주고 체크리스트 기반 루브릭으로 채점한다.
   (계층 구조, 시선 흐름, 정렬, 여백, 색 조화, 브리프와 맞는지)
2. **정량 지표:** 코드로 계산할 수 있는 건 모두 자동으로 잰다. 비전이 놓치는 작은 디테일을 보완한다.
3. **확대 검사:** 전체 화면과 함께 2~4배 크롭 이미지를 보여줘서 작은 결함까지 찾는다.
4. **best-of-K:** 후보를 3~4개 만든 뒤 나란히 비교해 순위를 매긴다. 절대 평가보다 상대 비교가 더 정확하다.
5. **수정은 diff로:** "로고 마크를 12% 키우고 baseline을 맞출 것"처럼 구체적인 수정 지시를 만들어 엔진에 다시 넣는다.

## 3. 부문별 전략

| 부문 | 주 엔진 | 보조 / 후처리 | 품질 포인트 |
|---|---|---|---|
| **UI / 웹 / 앱 화면** | HTML/CSS + 디자인 토큰 | Playwright 스크린샷, Figma 푸시 | 8pt 그리드, 타입 스케일, 컴포넌트화 |
| **로고 / 아이콘** | SVG 파라메트릭 (기하 프리미티브, 불리언 연산) | 생성 모델로 시안 → vtracer로 벡터화 → SVG 정리 | 작은 크기 식별성, 광학 보정 |
| **일러스트** | 생성 모델 (Figma generate_image) | 인페인트, 색 보정, 코드로 텍스트/레이아웃 합성 | 스타일 일관성 (시드, 레퍼런스 고정) |
| **픽셀아트 / 게임 에셋** | **PixelLab API** (캐릭터 4·8방향, 애니메이션, 타일셋, VFX, 인페인트) | 팔레트 양자화, 스프라이트시트 패킹 | 팔레트 고정, 프레임 간 일관성 |
| **포스터 / 편집 / 타이포** | HTML/CSS (Paged Media) → PDF/PNG | 생성 배경 + 코드 타이포 합성 | 한글 조판, 커닝, 그리드 |
| **데이터 시각화** | D3 / SVG | 대비·색각이상 시뮬레이션 | 정확성 + 가독성 |
| **3D** | three.js / Blender headless (Python) | 렌더 → 비전 비평 | 조명, 카메라 구도 |
| **모션** | CSS/Lottie/Canvas → ffmpeg | 프레임 샘플링 비평 | 이징, 타이밍 |
| **브랜드 시스템** | 위 엔진 조합 | 토큰 JSON, 가이드 문서 | 전 산출물 간 일관성 |

**원칙:** 텍스트, 로고, 정밀 레이아웃은 항상 **코드로** 처리한다. 생성 모델은 글자를 자주 깨뜨린다.
질감, 일러스트, 사진풍 이미지는 **생성 모델**로 처리한다. 둘을 합성해서 강점만 가져온다.

```
PIXELTEST/
├── atelier/
│   ├── brief/          # 요청 → Design Brief IR (스키마 + 검증)
│   ├── router/         # 부문/스타일 → 엔진 선택 규칙
│   ├── engines/
│   │   ├── svg/        # 파라메트릭 도형, 불리언, 아이콘 그리드
│   │   ├── html/       # 레이아웃, 토큰, 템플릿
│   │   ├── pixellab/   # PixelLab v2 클라이언트 (비동기 잡 폴링 포함)
│   │   ├── genimage/   # Figma generate_image 어댑터
│   │   └── blender/    # 헤드리스 3D 렌더
│   ├── post/           # 배경 제거, 벡터화, 팔레트 양자화, 업스케일, 합성
│   ├── render/         # Playwright/resvg/ffmpeg 공통 렌더러
│   ├── critic/         # 루브릭 프롬프트 + 정량 지표 (대비, ΔE, 정렬, 넘침)
│   └── export/         # 멀티 해상도, 스프라이트시트, 토큰 JSON, Figma 푸시
├── skills/             # Claude Skill: 부문별 디자인 지식 + 작업 절차
│   ├── design-foundations/   # 그리드, 타입 스케일, OKLCH 색 체계, 게슈탈트
│   ├── logo-icon/  ├── ui-screen/  ├── pixel-asset/  ├── poster/ ...
├── mcp-server/         # 위 기능을 MCP 도구로 노출 (render, critique, generate_*)
├── bench/              # 평가용 브리프 세트 + 결과 아카이브
└── docs/PLAN.md
```

**MCP 도구 (안):** `brief.create`, `render.html|svg|blender`, `critique.image`, `pixellab.*`,
`gen.image`, `post.vectorize|remove_bg|quantize`, `export.package`
→ 어떤 Claude 세션이든 같은 파이프라인을 쓸 수 있다.

**Skills:** 디자인 지식을 프롬프트가 아니라 **필요할 때 읽는 문서**로 둔다.
예: "로고 작업 시 → 콘셉트 5개 → 흑백 실루엣 먼저 → 16px 테스트 → 색 적용".

## 7. 평가 체계

- **벤치셋:** 부문별 브리프 10~20개 (고정). 버전마다 다시 돌려서 회귀를 확인한다.
- **자동 지표:** WCAG 대비 통과율, 팔레트 ΔE, 정렬 오차(px), 텍스트 오류, 반복 횟수, 건당 비용.
- **사람 평가:** 이전 버전, 기본 Claude, 새 시스템 결과를 이름을 가리고 나란히 비교 (A/B 선호도).
- **비전 비평 보정:** Critic 점수가 사람 평가와 맞는지 주기적으로 확인하고, 루브릭을 조정한다.

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 생성 API 비용 / 잔액 (PixelLab 현재 $0) | 저해상도로 먼저 탐색하고 확정된 것만 고해상도로 생성, 건당 예산 상한, 결과 캐시 |
| 비전 비평이 작은 결함을 놓침 | 정량 지표 + 확대 크롭 검사 병행 |
| 생성 모델 결과가 매번 다름 | 시드/레퍼런스 고정, 후보 여러 개 뽑아 선택, 레이어 분리로 부분 수정 |
| 저작권 / 스타일 모방 | 실존 작가·브랜드·기존 게임 스타일 복제 금지 규칙을 Router에 넣음, 원본성 체크 |
| 결과물을 고치기 어려움 | 항상 편집 가능한 원본(SVG/HTML/레이어)을 같이 제공 |
