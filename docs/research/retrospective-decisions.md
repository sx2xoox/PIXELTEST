# 반성: 왜 "산으로" 갔나 — 무기 아이콘 사례

## 무슨 일이 있었나
1. 3D 무기의 인벤토리 아이콘을 바닐라 도구처럼 2D로 손으로 그렸다. 3D 아이템 모델은 칸에서도 3D로 보인다는 걸 알면서도 "바닐라 도구 = 2D"라는 관례를 그대로 따랐다.
2. "왜 3D로 안 하냐"는 지적을 받았다. 그러자 각도를 자동으로 찾는 장치를 만들었고, 판정 기준을 세 번 바꿨다(경계상자 비율 → 면 넓이 → 투영 픽셀 수). 그동안 엉뚱한 각도가 계속 나왔다.
3. 결과가 안 좋자 "칸 전용으로 자루를 줄인 모델"이라는 새 장치를 또 만들었다.
4. 마지막에는 2D / 3D 그대로 / 칸 전용 3D 세 가지를 나란히 놓고 사용자에게 고르게 했다. 셋 다 별로였다.

정답은 단순했다. 옆모습을 정면으로 두고 자루를 45° 대각선으로 놓은 자세 4개를 렌더해서 눈으로 보고 하나를 고르면 됐다. 처음 보는 에이전트라도 그렇게 했을 것이다.

## 근본 원인
| 원인 | 실제로 한 일 | 했어야 할 일 |
|---|---|---|
| 자산 종류보다 관례를 먼저 따름 | 3D 모델에 2D 아이콘 | "이 자산이면 보통 어떻게 하나"를 먼저 묻는다. 3D 모델 아이템 = 칸도 3D |
| 눈으로 볼 수 있는 선택을 수식으로 풂 | 4,000개 각도 전수 탐색 + 점수식 3번 수정 | 표준 후보 3~6개를 렌더해서 보고 고른다. 수식은 고른 뒤 자동화할 때만 쓴다 |
| 결과가 나쁘면 장치를 더함 | 자루 줄이기 변형 추가 | 나쁜 원인부터 본다. 이번엔 미리보기에서 날이 화면 밖으로 잘린 걸 각도 문제로 오해했다 |
| 결정을 사용자에게 떠넘김 | 선택지 3개 제시 | 하나를 골라 내고, 한계는 한 줄로 쓴다. 선택지는 사용자가 물을 때만 준다 |
| 측정 통과를 품질로 착각 | checkFit 0건 = 완료 | 측정은 퇴행을 잡는 도구다. 마지막 판단은 실제 크기 화면을 바닐라 옆에 놓고 눈으로 한다 |

## 앞으로의 규칙(작업 태도)
1. 새 자산을 만들기 전에 그 분야에서 가장 흔한 방식을 한 문장으로 적고, 그 방식으로 먼저 만든다.
2. 시각적 선택(각도·색·구도)은 후보 3~6개를 렌더해 한 장에 놓고 눈으로 고른다. 자동 탐색은 같은 선택을 반복해야 할 때만 쓴다.
3. 결과가 이상하면 새 장치를 만들기 전에 미리보기 자체가 맞는지(잘림·배율·조명)부터 확인한다.
4. 보고는 결과 하나 + 한계 한 줄로 한다. "A/B/C 중 고르세요"는 하지 않는다.
5. 사용자가 지적하면 그 지적이 가리키는 가장 단순한 해법부터 한다.
