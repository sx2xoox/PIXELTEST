# 인벤토리 칸 맞춤(16×16) — 실측과 규칙

## 1. 바닐라 실측(item/*.png 823종, `fit.py`)
| 분류 | 경계상자 | 채움 | 질량 중심(가로/세로, 칸 중심 7.5 기준) | 최소 여백 |
|---|---|---|---|---|
| 전체 | 중앙값 15 (7~16) | 0.52 | 0.00 / +0.01 | 0 |
| 재료 41종 | 14 (8~16) | 0.43 | 0.00 (−0.45~+1.2) / +0.22 (−0.2~+1.5) | 1 |
| 도구 35종 | 14 (13~16) | 0.23 (0.20~0.33) | +0.63 / −0.50 | 0~1 |
| 갑옷 29종 | 12 (10~14) | 0.34 | 정확히 0 / −0.23 | 2 (1~3) |

**예시:**
- 주괴: 16×12, 채움 0.53
- 가루(레드스톤·발광석): 12×11
- 다이아몬드: 12×13
- 금 조각: 6×8(작은 조각은 의도적으로 작게)
- 막대·뼈·블레이즈 막대: 대각선 13~15, 채움 0.14~0.27
- 투구: 10×9, 위 여백 3, 아래 여백 4
- 흉갑: 14×13, 여백 1
- 각반: 10×12
- 장화: 14×10

## 2. 내 이전 결과의 문제
- **주괴:** 12×8에 가로 중심 +1.0이라 작고 오른쪽으로 쏠렸다.
- **가루:** 12×6, 위 여백 7이라 칸 바닥에 납작하게 깔렸다.
- **송곳니:** 세로로 세운 뿔이라 질량이 아래로 쏠렸다(+1.97).
- **투구:** 위 여백 0~1, 세로 중심 −2.1~−3.5라 칸 위에 붙었다.
- **흉갑:** 16px로 칸 테두리에 닿았다.
- **무기 아이콘 2종:** 16×16을 꽉 채웠다(채움 0.50~0.60, 바닐라 도구 0.23). 질량이 왼쪽 위로 쏠렸다(−1.4/−1.9).

## 3. 규칙(atelier/mc/slotfit.js)
1. 크기를 바꾸지 않는다. 픽셀아트는 축소하면 깨진다. 크기·채움 문제는 그리는 쪽에서 고치고, 위치는 `placeInSlot`이 정수 이동으로 맞춘다.
2. **질량 중심:**
   - 가로는 ±0.5 안이다. 좌우 대칭 아이템은 정확히 0이다.
   - 세로는 재료가 +0.4(바닥에 놓인 느낌), 투구가 −0.4, 장화가 +0.4다.
3. **여백:** 재료 ≥1, 갑옷 투구·각반 ≥2, 도구는 0 허용(바닐라 검도 모서리에 닿는다).
4. **아래가 넓은 형태(뿔·송곳니):** 세우면 내려앉아 보인다. 30° 눕혀 대각선으로 둔다(바닐라 뼈 문법).
5. **무기 아이콘:**
   - 왼쪽 아래 → 오른쪽 위 대각선 자루로 그린다(자루 2px + 외곽선).
   - 머리(날·촛대)는 위쪽 1/3에만 둔다.
   - 채움은 0.4 이하로 한다. 3D 모델의 모든 장식을 다 넣지 않는다.
6. **검증:** `checkFit(icon, kind)`가 빈 목록이어야 한다. kind는 material·small·rod·tool·helmet·chestplate·leggings·boots다.

## 5. 3D 무기의 칸 아이콘 — 2D로 그릴 필요가 없다(atelier/mc/javaitem.js, guirender.js)
- 1.21.4+ Java 아이템 모델은 칸에서도 3D로 그려진다(display.gui 변환). 칸 아이콘을 2D로 따로 그린 건 바닐라 도구를 따라 한 습관이었다.
- 바닐라 삼지창·망원경은 손에서는 3D, 칸에서는 2D를 쓴다. 긴 3D 물체를 16px 칸에 통째로 넣으면 머리가 3~4px로 작아지기 때문이다.
- 비교(GUI 배율 3 = 48px):
  - **3D 그대로:** 손에 든 모델과 똑같지만, 52칸짜리 낫이 칸 대각선에 들어가면서 가늘고 작다.
  - **칸 전용 3D:** 자루(머리 아래)만 0.3배로 줄인 변형이다. 머리가 2배 가까이 커져서 촛대는 초 3자루가 읽힌다. `select display_context`로 칸에서만 쓴다.
  - **2D:** 가장 또렷하지만 모델과 다른 그림이다.
- **자동 각도(fitGui):**
  - 자루가 왼쪽 아래 → 오른쪽 위 45°가 되는 회전 중에서, 칸에 실제로 찍히는 픽셀이 가장 많은(옆모습) 회전을 15° 격자 전수 탐색으로 고른다.
  - 처음에는 경계상자 비율로 판정했다. 45° 기운 가는 막대도 정사각형이라 실패했다.
  - 다음에는 면 넓이로 판정했다. 돌출 복셀 모델은 안쪽 면이 많아서 실패했다.
  - 그래서 투영 픽셀 수로 판정한다.
  - Minecraft는 회전을 Z → Y → X 순으로 적용하므로 "옆으로 돌린 뒤 화면에서 기울이기"는 세 축이 섞인 값이 된다.
- **본 회전:** Java 요소에는 본이 없다. 회전이 한 겹(한 축, 22.5° 단위)이면 요소 회전으로 굽고, 두 겹이면 오류로 알린다.
- **범위:** 요소 좌표는 −16~32만 허용된다. 쥐는 점에서 가장 먼 곳이 24칸 안에 들도록 좌표를 축소하고, display scale을 그만큼 키운다.
- **미검증:** 실제 게임 안 손 위치와 크기(바닐라 handheld 값 × 축소 보정), 칸 조명은 근사치다.
